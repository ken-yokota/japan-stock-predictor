# 追加したい予測要素は、実際に取れるのか

要望として挙がった予測要素を1つずつ、**無料データで取得でき、かつ過去に遡って
検証できるか**という基準で判定した記録です。判定日 2026-08-09。

「取れる」だけでは足りません。このシステムの採否ルールは「今の予測より精度が
上がったら採用」なので、**過去データが無い要素は、良いか悪いか永久に判定でき
ず、採用条件を満たしようがない**。リアルタイムでしか取れないものを ❌ にして
いるのは、この理由です。

判定は Yahoo Finance の日足を 2026-05-01〜2026-08-08 で実際に叩いて確認しま
した。「確認済み」は 68 営業日分が欠損なく返ったという意味です。

## S+ 板・気配値 (8:00〜8:59) — できません

一番効くはずの要素であり、実際そうだと思います。それでも入れられません。

**リアルタイムなら取れます。** auカブコムの kabuステーション API は板情報と
気配値を返します。ただし口座開設に加えて、Windows 上で kabuステーション本体を
常時起動しておく必要があります。SBI や楽天も同様に、証券口座に紐づいた
リアルタイム配信です。

**過去に遡ることはできません。** 板の履歴は JPX Data Cloud の FLEX Historical
などの有料商用データで、個人向けの無料公開はありません。ここが決定的です:

- 過去の板が無い → バックテストできない
- バックテストできない → 「今より精度が上がったか」を測れない
- 測れない → 「上がってたら採用」というルールを適用できない

つまり板を入れるという判断は、**効くかどうか分からないまま本番の予測式を
書き換える**ことになります。今のシステムを壊さずに比較する、という方針と
真正面からぶつかります。

### 代わりに入れたもの

寄り付き前の需給を、検証可能な形で近似します。

| 欲しかった情報 | 代わりに使うもの | 8:30時点で確定しているか |
|---|---|---|
| 8:00〜8:59 の日本株の気配 | 日経225先物 `NKD=F` (CME、06:00 JST 終了) | ✅ |
| 同上 | 日本株ETF `EWJ` (米国上場、05:00 JST 終了) | ✅ |
| 個別銘柄の寄り付き需給 | 対応ADRの前日値動き (05:00 JST 終了) | ✅ |
| ギャップの出やすさ | 前日のギャップ実績・ATR14・出来高比 | ✅ |

これらは板そのものではありませんが、「東京が閉まっている間に日本株の価格が
どこへ動いたか」を、検証可能な形で持ち込みます。

## PTS も同じ理由でできません

SBIジャパンネクスト PTS と Cboe Japan は、銘柄別の夜間セッション OHLC を
無料では公開していません。日次・月次の売買代金サマリは出ますが、銘柄ごとの
時系列ではないので特徴量になりません。リアルタイム気配は証券会社の口座経由で
見られますが、板と同じで履歴が無く、検証できません。

## 各要素の詳細

### S 🇯🇵 日本株先物

`NKD=F` (CME 日経225先物) を採用しました。日足の1本が、東京の大引けから翌朝
06:00 JST までを含みます。要望の「夜間騰落率」は、この日足の変化率がほぼその
ものです。

- **`NIY=F` (円建て) は使いません。** 直近の日足の 63% が出来高ゼロでした。
  出来高ゼロの終値は約定ではなく気配なので、指標として信用できません。
- `NKD=F` はドル建てなので、値動きに為替成分が混ざります。USD/JPY を独立した
  特徴量として持っているため、線形モデルは両者を分離できます。
- **TOPIX先物は入れていません。** 無料で検証可能なシンボルがありません。
  国内ETF (1306.T 等) は東京市場なので、8:30 時点では前日終値しか無く、
  前日終値なら既に持っている情報です。
- 大阪取引所の 08:45〜08:59 の先物気配そのものも、無料の履歴がありません。

### S 💱 為替

`EURJPY=X` `CNYJPY=X` `AUDJPY=X` `DX-Y.NYB` すべて確認済み。USD/JPY は既存。

### S 🛢 商品

`BZ=F` (Brent) `NG=F` (天然ガス) を追加。WTI・銅・金は既存。

### S 📈 米国セクター

半導体は `SOXX` (ETF) を使います。`^SOX` (指数そのもの) も値は返りましたが、
指数はライセンス次第で無料配信が止まることがあるため、実際に売買される ETF の
ほうを選びました。米国終値なので 8:30 時点で確定しています。

### A 😨 リスク指標

米金利は**変化率ではなく変化幅**で入れます。金利は既にパーセント表示なので、
「4.60% → 4.65%」を変化率にすると水準によって意味が変わってしまいます。
差分なら常に「5bp 上昇」を意味します。

### A 🏢 ADR・同業企業

18/22 銘柄に対応 ADR を割り当てました。

- NYSE上場 (厚い板・実約定): 7203 TM / 7267 HMC / 8306 MUFG / 8316 SMFG /
  8411 MFG / 8604 NMR
- 米国OTC (取得可・板は薄い): 9101 NPNYY / 9104 MSLOY / 1605 IPXHY /
  5020 JXHLY / 7201 NSANY / 7269 SZKMY / 7270 FUJHY / 8766 TKOMY /
  8001 ITOCY / 8031 MITSY / 8053 SSUMY / 8058 MSBHF
- 該当なし: 9107 川崎汽船 / 8002 丸紅 / 5019 出光興産 / 5021 コスモエネルギー

OTC は終値が薄い板の上に乗るため、NYSE 上場ほど信用できません。そのため
`focused` セットには NYSE の6銘柄だけを入れ、OTC は `extended` セットに回して、
効果があるかどうかを実測で判定させています。

### A 📅 イベント (決算・日銀・FOMC・CPI・雇用統計)

**決算日**は `config/earnings_dates.json` に既にあります (発表日程は事前公表
なので、使っても先読みにはなりません)。

**マクロ日程は今回入れていません。** 理由は取得性ではなく、統計的な理由です。
検証期間が最長でも 2026-06-01〜08-07 の約46営業日で、その間に FOMC は1〜2回、
CPI と雇用統計は各2回程度しかありません。数回しか立たないダミー変数は、
120営業日の学習窓の中では係数が定まらず、「効いた/効かなかった」を判定でき
ません。日程表を手で書き起こすコストを払っても、得られるのは判定不能な結果
です。数年分の履歴を貯めてから入れるべき要素です。

### A 🇯🇵 前日日本株 / B テクニカル

自銘柄の日足だけで作れるので、外部データが要りません。追加したのは
`overnight_gap` (前日の寄り付き ÷ その前の終値)、`volume_change_1d`、
`volume_ratio_20d`、`atr14_ratio`、`rsi14`、`ma5_deviation`、`ma60_deviation`
の7つです。

`overnight_gap` は同じ行の寄り付きから計算されます。寄り付きは 8:30 には
まだ存在しないので、**1営業日ラグを外した瞬間に先読みになります**。
ラグは `research/dataset.py` の1箇所に集約し、テストで固定しています。

## 増やせば当たる、ではない

要望の全要素を入れると予測要素は約80個になります。学習窓は120営業日なので、
**説明変数の数がデータ点数に迫ります**。Ridge は答えを返しますが、その答えは
少ない要素で学習したものより悪くなることが普通にあります。

そのため3つのセットを用意し、同一条件で走らせて実測で決めます。

| セット | 中身 | 予測要素の数 |
|---|---|---|
| `baseline` | 現行のまま。比較の基準なので凍結 | 25 |
| `focused` | 各テーマから1つずつ + 自銘柄のテクニカル | 約37 |
| `extended` | 要望の全部入り | 約80 |

判定は**方向的中率**と、それに対する**符号検定**で行います。勝率・損益は
BUY件数が十数件しかなく、良い方法と運の良い月を区別できないので、表示は
しても判定には使いません。

```
python -m cli compare-features --from-date 2026-06-01 --to-date 2026-08-07
```

比較結果は `artifacts/feature_comparison/latest.json` に出ます。
`baseline` に有意に勝ったセットが無ければ、**現行のまま何も変えません**。
