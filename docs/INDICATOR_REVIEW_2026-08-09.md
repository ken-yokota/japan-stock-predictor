# 指標の再検討 — 外部レビューの結論と、実装を見送った理由

実施日: 2026-08-09 / 記録日: 2026-08-10 JST

`docs/INDICATOR_RESEARCH_PROMPT.md` を ChatGPT と Claude に投げ、返ってきた提案を
検証した記録です。Gemini は回答が得られませんでした。

**結論から: 新しい指標は1つも実装していません。両モデルとも「今は足すな」で
一致し、こちらの検証でもその判断を支持する事実が出たためです。**

## 1. 両モデルが独立に到達した結論

独立した2つのモデルが同じことを言った点は、片方だけの主張より重く扱います。

| 論点 | 一致内容 |
|---|---|
| **優先順位** | 指標追加より**削減**と**定式化の変更**が先 |
| 現物指数の冗長性 | Dow は S&P500 と重複。削除候補 |
| ドル指数 | USD/JPY があれば不要 |
| 金 | 日中リターンとの経路がない |
| Baltic の三重計上 | BDI は Capesize/Panamax の加重平均。重複 |
| **クラックスプレッド** | **精製3社の利益ドライバーは原油価格ではなくマージン。構造的欠落** |
| 業種プールモデル | 銘柄別120観測 → 業種で360〜600観測へ |
| ギャップ2段階分解 | 海外指標は「寄り付きギャップ」を説明済み。日中は別問題 |
| 実行順序 | **12系列の復活 → 新Baseline確定 → 業種プール → 削減** |

ChatGPT の言い方が本質を突いています。現状で指標を足すと
「**本当に新指標が有効なのか、欠落している既存指標の代理をしているだけなのか
区別できない**」。

## 2. 提案シンボルの実在確認

推測で議論せず、全部実際に取得しました（2023-08-01〜2026-08-09）。

| 判定 | シンボル | 用途 |
|---|---|---|
| ⭕️ | BHP / GLNCY / XME | 商社（鉄鉱石・トレーディング・金属鉱業） |
| ⭕️ | RB=F / HO=F | クラックスプレッド合成用 |
| ⭕️ | VLO / XOP / CRAK | 石油（精製株・E&P・精製ETF） |
| ⭕️ | ZIM / AMKBY / MATX | 海運（コンテナ） |
| ⭕️ | STLA / MXNJPY=X / USDMXN=X | 自動車 |
| ⭕️ | DBC | 商品ETF |
| ❌ | **^BCOM** | **2026-07-17で更新停止** |
| ❌ | **^MOVE** | **2026-07-17で更新停止** |

15/17 は使えます。**指数ティッカー2本が死んでいました。**他が全部 8/7 まで来ている
ので休場ではなく配信停止です。指数はライセンス次第で無料配信が切れます。ETF は
生き続けるので、BCOM の代わりは `DBC` が使えます。MOVE に直接の代替はありません。

これはChatGPTが「商社の第2候補」と「金融で追加するならこれだけ」に挙げた2本です。

## 3. Claude の最重要指摘の検証

Claude は「`Adj Close ÷ Open` を使っていれば分割日に±60%の偽リターンが出る。
これが汚れていると以下の議論はほぼ無意味」と最優先で指摘しました。

**コードを読んだ結果、半分外れ、半分当たりでした。**

- ❌ **目的変数は正しい。** `services/dataset.py:435` は `Close ÷ Open − 1` で、
  両方とも未調整。偽リターンは発生しません
- ⭕️ **特徴量には混在がある。** リターン系は `adjusted_close or close`、
  日中系（`open_close_return`, `high_low_range`）は未調整

ただし Claude 自身が次のラウンドで訂正しています。調整係数は日境界でのみ変わるため
同一日の OHLC には同じ係数がかかり、`Close ÷ Open` では約分されて消えます。
つまり現状の組み合わせは、Yahoo が `Adj Open` を出さない制約下での最適解です。
**対応不要**。

## 4. 検出力の実測 — これが最大の発見

Claude は「検証基盤が13pp未満を検出できていない」と主張しました。実測しました。

| | Claude の想定 | 実測 |
|---|---|---|
| 同日22銘柄の級内相関 | 0.4（仮定） | **0.082**（生データ） |
| 実効サンプル | 115件 | **395件** |
| 検出可能な効果 | 13pp | **3.1pp** |

数値は過大でしたが、**核心は正しい**。ペアリング後の実効サンプルは約101件で、
検出限界は方向的中率で **約3.1pp** です。

これまで測った4案は +0.19〜+0.93pp。**すべて検出限界の1/3以下**でした。

> **「有意差なし、不採用」と報告したのは不正確でした。**
> 正しくは「この検証基盤では判定できない」です。

新しい指標を足しても、同じ p ≈ 0.6 が返ってくるだけです。**検出力を上げない限り、
指標の良し悪しは永久に分かりません。**

## 5. 両モデルの相違点と、こちらの判断

| 論点 | Claude | ChatGPT | 採用した判断 |
|---|---|---|---|
| 横断面ランキング | **1位**（実効サンプル9倍） | **やるな**（運用目的が変わる） | **ChatGPT寄り**。ただし「測定装置として」は有効 |
| 業種プール | 2位 | 2位 | 一致。ここから着手 |
| 削減の中身 | 20日系・US 2Y・Dow | Dow・DXY・US 30Y | **Claude寄り**（US 2Y は線形従属） |
| JGB | 最下位 | 5位 | 一致。後回し |

**横断面ランキングについて**: ChatGPT の反論が正しい。「全銘柄下落、トヨタ −0.5%、
他 −2%」はランキング1位でもロングでは損失です。目的が変わります。
ただし Claude の「シグナル検証用の測定装置として先に作り、横断面で有意な指標だけを
方向モデルに戻す」という二段構えは筋が通っており、業種プールの後に検討します。

**US 2Y について**: `2Y = 10Y − (10Y − 2Y)` は恒等式です。3本とも持つと
**設計行列がランク落ち**しており、情報損失ゼロで11特徴量削減できます。
DXY より先に削るべきです。

**ただし DXY・金・WTI・Brent は今削っても1特徴量も減りません。** すでに予測に
届いていないためです（次項）。これらは「削減案件」ではなく
「**復活対象から外す案件**」です。

## 6. 12系列が届いていない本当の理由

当初「07:00取得と08:30鮮度判定の矛盾」と診断し、P0として記録しました。
**DBを確認したところ、その矛盾はまだ一度も発現していません。**

```
market_data の interval:        eod のみ 16,357件
interval='live_snapshot' の行:  0件
services/ingestion.py:98:       include_snapshots=True   ← コードは正しい
daily_runs:                     1件（手動bootstrap、PARTIAL）
```

**朝のpipelineが一度も完走していないだけ**でした。2026-08-10 07:00 が初回実行です。

仮に鮮度判定を直しても即座には使えません。スナップショット特徴量は日次観測が
蓄積されてから学習に入る設計で、120営業日ぶんは**約6ヶ月**です。

**意思決定を6ヶ月待たないための道**: 研究経路（`research/`、Yahoo直接取得）なら
12系列を今すぐ使えます。両モデルが求める「正常なBaseline」は、そこでなら作れます。

## 7. 実行順序（両モデルの一致 + こちらの検証）

```
0. 12系列を含む正常なBaselineを研究経路で確定
     ← 原油の無い石油会社モデルに何を足しても測れない
1. 検出力を上げる
     ← 3.1ppが限界では、どの施策も判定できない
     期間の延長 / Rank IC / 日付単位block bootstrap
2. 業種プールモデル
     ← 訓練観測を3〜5倍に。alpha張り付きの解消
3. 削減 (US 2Y → Dow → 20日系)
     ← US 2Y は情報損失が数学的にゼロ
4. クラックスプレッド・BHP・ZIM 等の新規指標
     ← 1〜3が終わって初めて意味のある検証ができる
5. JGB利回り（財務省CSV）/ 横断面ランキング / ギャップ2段階分解
```

**4を先にやってはいけません。** 現在の検証基盤では、有効な指標と無効な指標が
どちらも p ≈ 0.6 として返ってきます。
