# メール形式（承認済み）

> **実装は `notifications/report_layout.py` にある。**
> 予測メール・結果メール・進捗メールはすべてこのモジュールで組む。
> HTMLを手書きしない。進捗メールは `scripts/send_status_report.py` に
> JSONを渡して送る。読みやすさを人の心がけではなくコード経路の性質にする、
> というのがこの構成の目的。


2026-08-11に運用者が承認した形式。予測メール・結果メール・進捗メールの
3種類すべてに適用する。**この形式から外れたメールを送らない。**

承認の経緯: それ以前の形式は「とても見づらい」との指摘を受け、
1銘柄1ブロックの箇条書きから、色付きHTMLの表に作り直したもの。

---

## 全メール共通の骨格

| 要素 | 仕様 |
|---|---|
| 本文 | HTMLを主とし、text/plainを代替として必ず添える |
| 幅 | `max-width:680px`、中央寄せ、白地カードに角丸 |
| 表 | `overflow-x:auto`で囲む。スマホで横スクロールできること |
| 見出し | 左に4pxの縦罫、16px |
| リード文 | 見出し直下に1行。件数・合計・ルールなど要点だけ |
| 末尾 | 免責または「操作の要否」を1行 |

### 色

| 用途 | 色 | 使いどころ |
|---|---|---|
| 上昇・成功 | `#15803d` | プラスのリターン、的中、完了 |
| 下落・失敗 | `#b91c1c` | マイナスのリターン、外れ、上限到達 |
| 本文 | `#111827` | 通常の文字 |
| 補助 | `#6b7280` | 単位、理由、参考値 |
| 表の見出し | 背景 `#1f2937` / 文字 白 | ヘッダ行 |
| 強調行 | 背景 `#ecfdf5` | 買い候補、完了項目 |
| 交互の縞 | 背景 `#f9fafb` | 長い一覧の可読性 |

**数値の符号は必ず色を付ける。** 符号だけでは電話で読み取れない。

## 1. 予測メール

件名: `【日本株AI予測】YYYY-MM-DD 寄り付き→大引け／買いN銘柄`

リード文には、判定ルール（予測リターンの閾値と上昇確率の閾値）を必ず入れる。
なぜその銘柄が選ばれなかったのかが、ルールなしでは読めない。

| 順 | セクション | 列 |
|---|---|---|
| 1 | 買い候補 | 順位・銘柄・予測リターン・上昇確率・前日終値・予測終値 |
| 2 | なぜその予測になったか | 銘柄ごとに寄与の大きい要因4つ（寄与・要因） |
| 3 | 全銘柄 | 銘柄・判定・予測リターン・上昇確率・前日終値 |
| 4 | 注意 | 優位性未確認の明記、取得状態の但し書き |

セクション2が運用者の要望の中心。特徴量の内部名ではなく日本語にする
(`us_10y_minus_2y_spread__return_20d` →「米10年-2年金利差の20日リターン」)。
寄与はモデルの計算そのもので、全要因の合計と切片が予測値に一致する。

セクション3は買わなかった銘柄も含めて全件出す。欠けている銘柄が
「予測がない」のか「載っていないだけ」なのかを区別できるようにするため。

## 2. 結果メール

件名: `【日本株AI結果】YYYY-MM-DD 答え合わせ／買いN銘柄 X勝Y敗 ±Z円`

件名だけで勝敗と損益が分かること。運用者は本文を開かずに判断する。

| 順 | セクション | 列 |
|---|---|---|
| 1 | 成績 | 区分・銘柄数・方向的中・平均実績・合計損益（買い/全銘柄の2行） |
| 2 | 買った銘柄の結果 | 銘柄・予測・実績・的中判定・始値→終値・損益（損益順） |
| 3 | 買わなかった銘柄 | 銘柄・予測・実績・見送りの理由（実績順） |
| 4 | この数字が示していないこと | 標本数の限界を必ず書く |

セクション3の「見送りの理由」は、どの閾値に何%足りなかったかまで書く
（「確率が58%で閾値未満」）。「NO_BUY」だけでは判断を再現できない。

セクション4は削らない。1日5取引の結果を成績として読ませないための節。

## 3. 進捗メール

件名: `【進捗 n/m】...` — 分数を件名に必ず入れる。

| 順 | セクション | 列 |
|---|---|---|
| 1 | 作業中 | No・内容・想定・経過・完了目安 |
| 2 | 今夜の残り | No・内容・想定・状態 |
| 3 | 自動で進むもの | 時刻・内容・状態 |
| 4 | 以降のタスク | No・内容・想定・優先度 |
| 5 | 完了したもの | 内容・結果 |

状態はバッジで示す（実行中は青、完了は緑、待機は灰、警告は橙、失敗は赤）。

進捗メールの送信規則（頻度・1工程1通・表の使用）は
`.claude/skills/working-agreements/SKILL.md` と
`.claude/skills/email-status-reports/SKILL.md` にある。
本書はその見た目を定める。
